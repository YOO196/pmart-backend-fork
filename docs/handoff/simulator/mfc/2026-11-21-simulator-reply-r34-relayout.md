# 회신 — R-34 MFC 평면 재배치, 모든 칸 위치 다시 등록 (2026-11-21, PC 3 mfc)

보낸 영역: mfc(PC 3). 요청: pmart-mfc-simulation `docs/backend-requests.md` R-34(시뮬레이터 main f51a4db).
사용자 결정(2026-11-21): "입고구역 근처에 냉동냉장구역이 있어야". 배치는 서쪽 냉장 B | 냉동 A, 가운데 입고·검수(북쪽 차량문)와 상온 C~H, 동쪽 휴게·사무 → 상온 입고창고 → 패킹이다.

## 1. 바꾼 것 — LAN seed `deploy/lan/seed/mfc_layout.py`(서버 코드 변경 없음)
- **위치 파일**: `docs/simulator/mfc/layout/location-positions.json`. 시뮬레이터 `docs/layout-export/location-positions.json` f51a4db 사본이고 15,534칸이다.
  - 선반 14,559, 보충재고 랙 900, 대형 묶음 16, 바닥 자리 59.
- **새 단계 `r34`**: 파일의 모든 칸 위치(xM·zM)만 바꾼다(PUT, 지금 값 그대로 + position).
  - 칸 코드·구역·온도대·치수·reserveStock·상태는 건드리지 않는다.
  - 닫힌 칸(R-33 에서 닫은 94칸 등)도 위치는 맞춘다.
  - 이미 같은 위치(소수 둘째 자리 허용 오차)면 건너뛴다. 다시 돌려도 된다.
  - 서버에 없는 칸은 건너뛰고 알린다. 지금 LAN 에는 그런 칸이 없다.
- **다른 단계도 이 파일 값을 쓴다**(`pos_of`). `register`·`support`·`r33` 을 나중에 다시 돌려도 옛 좌표로 되돌아가지 않는다.
  - layout.json(옛 평면)은 고치지 않았다. 위치의 정본은 이 파일이다.
- **RTN-A-01**: 파일에 없어서 서버 좌표(38.6, 22.0)를 그대로 둔다.
  - 새 평면에서 이 자리가 맞는지는 확인이 필요하다. 회수품 반입 자리를 정하면 알려 달라.
- **R-33 과의 관계**: #330·#331 은 병합됐고 PC 1 이 LAN 에서 실행했다(11-21 읽기 확인). 지금 R1 칸은 ACTIVE 900·CLOSED 90, R2 칸은 ACTIVE 16·CLOSED 4 다.
  - 닫기는 그대로다. 상온 랙·대형 묶음·RCV-A-02 좌표는 이 파일 값으로 바뀐다.
