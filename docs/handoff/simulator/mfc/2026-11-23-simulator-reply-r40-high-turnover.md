# 회신 — R-40 고회전 상품(주문 상위 20) F 구역 적치 (2026-11-23, PC 3 mfc)

보낸 영역: mfc(PC 3). 요청: 시뮬레이터 세션 "mfc 시뮬3" R-40. 사용자 "많이 팔리는 물품 자동으로 거기로 적치해" → "고회전 시험 말고 이제 진짜 고회전 상품(주문율 높은 상품 top20)은 거기에 적치". 근거 업무 문서 2-1 "F 상온 고회전 — 카테고리 무관 인기 SKU".

## 1. 정한 것(사용자, 11-23 이 세션)
- 주문율 = **최근 7일 주문 줄 수**(확정·인계된 예약 — 결제 전 만료·취소는 안 셈). 상온만.
- 다시 계산 = **하루 한 번**(서비스 시작 2분 뒤 첫 계산, 그다음 24시간마다).
- 기존 재고 = **다음 적치부터만**. 이동 작업은 만들지 않는다. 한 상품이 잠시 F 와 다른 칸 두 곳에 있을 수 있다.

## 2. 바꾼 것
- mfc-inventory 0.45.0(V30): 센터마다 상위 20 상온 SKU(`high_turnover_sku`). 적치·복귀 칸 추천(`placement-suggestions` → mfc-inbound 적치 작업 `suggestedPlacements`·`suggestedToLocations`)이 이 상품에 **F 구역 고회전 칸 먼저** — 그 상품이 이미 있는 F 칸 → 다른 F 칸(코드 순) → 안 들어가면(큰 상품·칸 가득) 예전 순서(그 상품 칸 → 기타 칸 → 보충재고).
- 순위 밖 상품에는 F 칸을 추천하지 않는다(F 피함).
- F 칸 = 위치 고회전(`highTurnover`) + 구역 글자 F(A-F1~F4). 예전 E2E 시험 고회전 칸(A-H1-01 …)은 구역 글자가 달라 추천에 안 쓴다.
- LAN seed `mfc_layout.py r40`: 상온·보관·보충재고 아님·구역 F 칸을 고회전으로. 부산 미리 보기 1,440칸(카테고리 칸 0).

## 3. 실행(PC 1, 사용자 확인 뒤)
1. PR 병합 → mfc-inventory 배포.
2. 부산 `python -I deploy/lan/seed/mfc_layout.py r40plan` → `r40`. 목포 `PMART_MFC=MFC-MOKPO-01 PMART_SUP_ACCOUNT=claude-mfc-sup-mk` 로 같은 단계.
3. 순위는 배포 2분 뒤 자동 계산. 주문이 7일 안에 있어야 순위가 생긴다(목포는 주문이 쌓인 뒤).

## 4. 시뮬레이터에 알릴 것
- 서버 재고 위치를 그대로 그리면 된다. 순위 목록을 보이는 API 는 만들지 않았다(필요하면 요청).
- 한계: 고회전 칸은 보충재고에서 자동 기본 보충되지 않는다(관리자 보충 기준이 있어야 함 — Q-07 과 이어짐). 입고 적치는 F 로 바로 간다.
