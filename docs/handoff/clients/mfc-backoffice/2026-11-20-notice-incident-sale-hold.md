# 알림: 품질 사고를 등록하면 영향 LOT 을 판매 보류 — 센터 관리자 화면 (mfc-quality 0.10.0)

- 보낸 영역: mfc (PC 3 백엔드)
- 작성: pmart-backend, 2026-11-20
- 대상: pmart-clients `web/mfc-backoffice`(품질 사고 등록·상세)
- 배경: 사용자 결정(2026-11-20) "품질 사고를 열면 그 LOT 출고를 막는다 — 격리가 아니라 판매 보류"(업무 문서 IV-09 "범위 불명 보류"). 전에는 사고가 열려 있어도 같은 LOT 이 계속 고객에게 나갔다.
- 배포: 백엔드 PR 병합·배포 뒤(PC 1). 게이트웨이 변경 없음(기존 `/quality-incidents` 경로).

## 1. 등록 — `POST /api/v1/quality-incidents` 에 `saleHold`(선택, 기본 true)
- 켜 두면(기본) 영향 LOT 의 **이 센터 정상 재고**가 판매 보류된다: 판매 가능에서 빠지고, 집품·이동·적치가 막히고, 그 LOT 으로 잡힌 아직 집지 않은 주문은 다른 LOT 으로 다시 잡힌다(못 잡으면 기존 결품 흐름).
- 이미 집품·포장·인계한 것은 그대로다 — 인계된 주문 수는 지금처럼 `affectedOrderCount`.
- 격리가 아니다. 실물 격리·해제·폐기는 지금처럼 판정(`POST /quality-decisions` 의 `incidentId`)·폐기 요청으로 한다.
- 화면: 등록 폼에 "판매 보류(기본 켬)" 체크 하나. 끄는 경우 = 한두 개 파손처럼 LOT 전체를 막을 필요가 없을 때.

## 2. 상세·목록 — `affectedLots[].saleHold`
| 값 | 뜻 | 화면 표시 예 |
|---|---|---|
| `HOLD_PENDING` | 거는 중(재고 서비스 응답 대기 — 30초 안팎에 다시 시도) | 판매 보류 거는 중 |
| `HELD` | 판매 보류 중 | 판매 보류 중 |
| `RELEASE_PENDING` | 푸는 중 | 푸는 중 |
| `RELEASED` | 풀림 | 풀림 |
| `null` | 보류 안 함(끈 등록·자동 사고·이전 사고) | (표시 없음) |

- 풀리는 때: 그 LOT 이 처리되면(격리 해제 APPLIED 또는 폐기 승인 — 지금 `resolved` 와 같은 기준) 그 LOT 만, 사고를 닫으면 남은 LOT 모두. 같은 LOT 에 열린 다른 사고가 있으면 재고 쪽 보류는 마지막 사고가 풀 때 풀린다.
- 판매 보류는 재고 > 분실 조사 목록(`stock-holds`)에 나오지 않는다(실사·정정 대상이 아님).
