# 회신 — BR-52 R16 표시 문서 번호(`documentNo`)는 새로 만들지 않는다

보낸 영역: mfc
- 작성: pmart-backend PC 3(mfc), 2026-11-20
- 원 요청: pmart-clients `docs/handoff/mfc-app/2026-11-10-backend-pda-work-areas.md` R16(채번 지침 G-02 `TSK-20261110-000123`, PDA 응답 7곳에 `documentNo`)
- 사용자 결정(2026-11-20):
  - "이미 있으면 기존거 써"
  - "문서번호는 백앤드 인식할 때 쓰라고 있는 거고 관리자가 볼 땐 간단하게 정한 공통규칙 그걸로 보이게 해야지"

## 정한 것
- **새 `documentNo` 를 매기지 않는다.**
  - 백엔드가 알아보는 번호는 지금 있는 ID 를 그대로 쓴다: 작업 `taskId`, 입고 예정 `trfId`, 입고 작업 `taskId`, 이동 지시 `moveId`, 실사 `sessionId`, 포장 `packageId`.
  - 이 ID 들은 서버 로그·문의 대조용이다. 화면에서는 상세의 "시스템 번호" 칸에만 둔다(ADR-0070).
- **사람이 보는 표기는 ADR-0070 공통 규칙을 따른다.** 새 번호 체계를 만들지 않는다.

| 대상 | 화면 표기 | 받는 값 |
|---|---|---|
| 주문에서 나온 작업(피킹·패킹·복귀) | 주문번호 + 종류 — `20000001 피킹` | `orderNumber`(작업 목록·상세에 있음) |
| 포장 | 라벨 숫자 4자리(옛 포장 6자리) | `handoverCode` |
| 입고 예정·입고 작업 | 송장 번호 `TRF` 그대로 + 종류 — `TRF-… 입고` | `trfId`(송장 라벨 `TRF:{trfId}:{version}` 의 그 값 — CDC 가 정함) |
| 주문이 없는 작업(적치·이동·보충·격리 이동·실사) | **종류 · 칸 · 시각** — `적치 · A-C1-04-2-02 · 14:05` | 작업 종류·칸 코드·만든 시각(응답에 있음) |
| 라이더·직원 | `김*수 · 482913`, `홍길동 · P2026-00001` | rider display-names, 직원 이름 조회 |

- 같은 기준을 MFC 백오피스(PC 3)도 쓰고 있다(ADR-0070 "화면 표기를 아직 못 받는 대상은 종류 · 시각").

## 앱에 바라는 것
- PDA 목록·카드에서 내부 ID 를 지우고 위 표기로 보인다. 상세에는 접힌 "시스템 번호" 칸만 둔다.
- 서버 변경은 없다. 위 표의 값은 지금 응답에 모두 있다.
